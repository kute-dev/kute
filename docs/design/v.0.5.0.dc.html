0.5.0

Flux CD support — GitOps state becomes an answer, not a CRD dump

Flux clusters already work today — Kustomization and HelmRelease are CRDs, so they get the generic list/detail/search from 14a/14d for free. 0.5.0 promotes them to curated registry entries: real columns, real status derivation, real verbs. The vision fence holds — kute never installs or bootstraps Flux (not a deployment pipeline); it reads, reconciles, and suspends. And like Helm-without-the-helm-binary (18a), every Flux verb is a plain API call — the flux binary is never required.

  • Condition message verbatim, on the row — the health-check failure renders exactly as Flux wrote it (principle 4), and ↵ routes to the failing object, not to the Kustomization's describe page.

  • This is the whole point of Flux support — the timeline's question is "what changed?", and on a GitOps cluster the true answer is a commit. Revision-applied events (◆, the only purple marker) slot into the existing deduped stream; reading top-down gives the causal chain: commit → rollout → OOM → backoff.
  • No new machinery — Flux controllers already emit these as Kubernetes Events; kute's dedup + enrichment attaches the commit subject from the source artifact. Works on 16a unchanged for non-Flux clusters: no Flux, no ◆ rows, zero chrome (principle 6).
  • Routine no-change reconciles collapse into the "quiet" line — 22 identical events would otherwise bury the one revision that mattered.
  • `v` copies `main@8f3c2a1` — the thing you paste into `git show` or the incident channel.
