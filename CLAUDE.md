# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

TUI Kubernetes console (Bubble Tea + Lip Gloss). 

Design spec: `docs/design/README.md` (source of truth for screens, layout, tokens, keys, glyphs).

`docs/lazy-informers.md` explains how the data layer decides what to fetch and when — read it before changing anything about informer startup, cache reads, or discovery.


## Invariants — never violate

- **No hex color literals in view code.** All colors come from the semantic `Theme` struct (dark + light variants live in one file). New UI = new token if needed, never an inline color.
- **Both themes always.** Any new surface must define/reuse tokens that work in dark and light; test both.
- **Every verb goes through the command registry.** Key, label, destructiveness tier, applicable kinds — keybar, help overlay, and confirm flow render from it. Never hand-wire a keybinding in a view.
- **Destructive-action policy:** reversible-and-immediate verbs (e.g. cordon) execute right away; delete and rollout restart are both tiered — inline y/N in non-prod, type-the-name modal in PROD contexts (kubeconfig annotation, never a name heuristic); drain/force-delete always modal. Red borders are reserved exclusively for destructive confirms.
- **Resource kinds are registry entries**, not bespoke screens. New kind = columns + status derivation + verbs registered on the shared list/detail skeleton.
- **Render functions are pure**: f(model, theme, size). No I/O, no clock reads, no globals in render paths.
- **All cluster access goes through the `ClusterProvider` interface.** UI code never imports client-go directly. The fake provider must stay feature-complete for tests/demo mode. The two lister decorators in `internal/app` embed `resources.RawLister`, which promotes only `ListRaw` — every optional seam (`Synced`, `KindSynced`, `CountLive`, …) needs an explicit forward, and a missing one is *silent*: the consumer type-asserts, misses, and takes its fallback path. Add the compile-time assertion in the same commit as the seam. One unforwarded `CountLive` made the jump palette count informer caches instead, starting an informer per kind on the update loop and hanging the app for a minute.
- **The app pays for the screen you're on.** Connect starts three informers (Namespace, Pod, Node); every other kind's informer starts when something first reads it, from inside `ListRaw`. Two rules follow and are easy to break by accident: **never read a cache breadth-first** (a loop over every registered kind starts every informer — that's what `Cluster.CountLive`'s one-object metadata list exists for, and why the goto palette and empty-state hints skip un-started kinds), and **never gate a loading state on `Synced()`** — it's a connect latch, not cache state; `KindSynced(kind)` is the per-kind answer, and it deliberately reports settled for anything that will never arrive (stopped cluster, no informer, Forbidden, or an initial LIST that keeps failing) so a spinner can't hang. Settled is not the same as empty: `KindError(kind)` carries the reason a cache stopped filling and **must** be shown when it's non-nil (`tui.KindsError`, right after the `KindsSynced` gate) — without it the anti-hang rule just trades a spinner for the false claim that the cluster has none of that kind. A screen reading a kind it doesn't display must also reload on it (`browse`'s `auxKinds`), or its cells go stale. **An empty state is a claim about the cluster** — never enter one without checking the backing caches have filled (`tui.KindsSynced` + `ScheduleCacheSyncRetry`); the retry matters because a kind with genuinely zero objects syncs without emitting a change event, which is exactly the case where "empty" is correct.
- **Persisted state is versioned.** Any change to the recents/perContext schema bumps the version and adds a migration.
- **One palette shell** parameterized by scope (goto/namespace/context) — never fork it.
- **Aliases are reserved for the ~8 built-in daily kinds** (p d s i n c e) and are always the kind's first letter, rendered as a highlighted first letter — never a chip. Aliases re-rank to rank 1, never fire instantly. CRDs and the long tail never get them.
- **CRD support is data, not code.** Discovered kinds become kind-registry entries from API discovery (printer columns → columns, Ready-style condition → status, else neutral). No per-CRD layout code, ever. Deleting a CRD always gets the type-the-name modal. Discovery must never list CRD *objects* — they carry the full OpenAPI schema for every served version (2.76 MB across 48 CRDs on a real cluster, 98% of it unread). It reads CRD *names* via the metadata client plus the discovery API; printer columns arrive per-kind on first read, so "else neutral" is the interim state of a real kind, not only a fallback for CRDs that declare none.
- **Forwards are a registry kind** on the shared list skeleton, global and session-scoped; a failing forward may only change the header chip color — never a modal or banner over unrelated screens.

## Conventions
- Status glyphs, key vocabulary, and mode-pill hues per the design README — don't invent alternatives.
- `j/k` ≡ `↑↓` everywhere; `esc` always walks back exactly one level.
- Watch-based updates, not polling (metrics poll on the sync interval only). The two deliberate one-shot reads are `CountLive` (palette counts, which must not start informers) and 8a's live `managedFields` fetch — neither is a poll.
- Terminal capability degradation: 256-color palette mapping (via termenv) and ASCII substitutes for exotic glyphs (`◈ ⧗ ▐ ◌`) are the decided fallback path; a minimum-terminal-size guard screen is decided but not yet built.
- **Every text buffer routes paste through `tui.RoutePaste`** (`internal/tui/paste.go`), called at the top of the screen's `Update` with a `pasteTarget()` resolver that mirrors that screen's own key-routing precedence and returns nil when no buffer is open. A screen that only handles `tea.KeyPressMsg` silently drops every paste: a terminal's bracketed paste arrives as one `tea.PasteMsg` that never passes through a key handler, and bubbles' own `ctrl+v` binding answers with an unexported message no screen can route (which is why `RoutePaste` claims the chord first and replies with `tui.PasteCmd`). Two silent-failure traps in a resolver: build it on a **pointer** receiver, and point it at the **focused** buffer — `textinput.Update` no-ops when blurred. If the edit has a side effect (re-filter, re-match, clamp), do it inside the returned closure, or a pasted query will sit in the box without narrowing anything.

## Workflow
- After UI changes, run the golden-file snapshot tests (both themes) and update intentionally-changed snapshots only.
- New screens/verbs: update the command registry and kind registry first; views follow.
- Commit messages: `type(scope): short imperative description`, lowercase, one focused line, no trailing period, no Co-Authored-By. Match the granularity of the change — e.g. `build(deps): bump go module dependencies, k8s.io to v0.36.2`, `ci(pages): pin workflow actions to commit SHA`. Avoid vague messages like "update deps" or "fix stuff"; name what actually changed. `feat`/`fix`/`perf` subjects flow verbatim into the release changelog and 28b's what's-new panel (git-cliff, see `cliff.toml`), so write the description as the user-visible *effect*, not the implementation: `fix(tui): stop the 7b help overlay truncating every key-hint row` is a good subject; `fix(verbs): give the dead Mutating field a real reader` means nothing to a user and git-cliff can't fix prose, only filter it.

Tooling is pinned via **mise** — `mise.toml` is the authoritative list of versions (go, kubectl, golangci-lint, git-cliff, govulncheck, kind, betamax, and `gopls`, which backs Go code intelligence via the LSP tool; prefer `findReferences`/`goToImplementation` over grep when changing an interface seam like `ClusterProvider`/`RawLister`/`Mutator`, where a missing forward behind an embedded type is silent). `KUBECONFIG` is set in `mise.toml` to `{{config_root}}/.kube/config` (repo-relative, gitignored — every checkout gets its own, no machine-specific setup needed); the app also falls back to `~/.kube/config` and then in-cluster config. Run `mise install` to get the pinned toolchain.

## Architecture

Layered, with the TUI depending on `kube` only through interfaces so screens can be tested without a live cluster.

- **`cmd/kute/main.go`** — thin entry point; calls `app.Run()`.
- **`internal/app`** — composition root. `NewModel` builds a `kube.Cluster` (real cluster, informer-backed) or a `kube/fake.Cluster` (`--demo`) and roots the model at `tasks/browse`, injecting it as the `resources.RawLister` and `browse.MetricsReader` seams and wiring an `OpenLogsFunc` that pushes `tasks/podlogs` for the selected pod. `RunWithConfig` starts the eager informers (or the demo fake's event loop) and pipes both resource-change and connection-state events into the program. If no cluster is reachable and `--demo` isn't set, `browse` still renders, in an error state carrying the real connection error (`browse.Config.InitErr`). This is the only place real Kubernetes wiring happens.
- **`internal/kube`** — Kubernetes access. Defines domain structs (`Pod`, `PodMetrics`, `Context`, `ResourceKind`, `ConnState`, `Event`), one-shot/`Client*` readers, and `Cluster` (shared informer factory + `PodMetricsByNamespace` + watch/conn-state events). Every typed kind's informer, cache reader, GVR and scope lives in **one `typedKinds` table** (`watch.go`) — the single registration path, because reaching for a factory's `Lister()` registers that informer as a side effect, and a registration that skips the table gets started later with no watch-error handler attached. `ListRaw` dispatches through it and calls `ensureKind` first, which is where laziness lives; `KindSynced(kind)` is the per-kind cache-fill signal the UI's loading states gate on, and `CountLive` counts a kind server-side (`limit=1`, `remainingItemCount`) without touching an informer. Caches strip `managedFields` on the way in (`transform.go`), so the one screen that shows them (8a) fetches them live. Helm releases get their own Secret informer, filtered server-side to `type=helm.sh/release.v1`, rather than reading the shared Secret cache — and, uniquely among the kinds, one such informer *per namespace read* rather than a single cluster-wide one (release Secrets are individually large: 8.19 MB cluster-wide against 4 MB for one namespace on a real cluster, which over a VPN is the difference between a screen that loads and one that never does — see `docs/lazy-informers.md` §5.5 before generalising it to another kind). Write access is the narrow `Mutator` interface (`DeleteResource`, `DeleteResourceForced`, `Cordon`, `Drain`, `RolloutRestart`), implemented on `Cluster` and called from `browse`/`poddetail` (delete), `browse`/`nodedetail` (cordon/drain), and `browse` (Deployments' `ctrl-r` rollout-restart, inline `y/N` confirm) via `actions.Controller`. Event reads (`ObjectEvents`, `NamespaceEvents`) back `poddetail`'s EVENTS grid and the `events` (9b) screen. **Exec credential plugins (GKE/EKS/kubelogin) never touch the terminal** (`execauth.go`, `docs/managed-clusters.md`): every REST config gets `ExecProvider.StdinUnavailable`, and client-go's Authenticator is constructed with `os.Stderr` swapped for a pipe kute drains — both decisions are frozen at *first client construction* for a given exec config, so they belong in `newClientForContext` and nowhere else. A credential failure is its own `ConnPhase` (`ConnUnauthenticated`), counts as `Offline()`, carries the plugin's own stderr in `ConnState.Err`, and **stops the /livez ping loop** — re-running a plugin that just failed is not a retry strategy, so recovery is 4a/4c's explicit `r`. Consuming *read* interfaces (`resources.RawLister`, `browse.MetricsReader`, …) are declared **in the packages that use them**, not here — so `kube` has no dependency on `tui`.
- **`internal/resources`** — the resource catalog: `Descriptor`/`Registry` (per-kind columns, projection, health tallying/labeling), `Group`s, `columns.go` (`components.Column`/`Cell` specs per kind), and `List`/`Count` over a `RawLister`. Kind-agnostic; drives `browse`.
- **`internal/tui`** — root model (`Model`, task stack, palette/help overlay routing), Chrome v2 (`Screen`/`Frame`), the semantic `Theme`/`Styles`, `glyphs.go`, `verbs` (the keybar/help/confirm verb registry), and `actions` (the shared confirm→execute controller). No pre-redesign chrome remains as of Phase 6.
- **`internal/tui/components`** — reusable stateless renderers: `table` (the inverted-layout table), `bar` (CPU/MEM mini-bars), `overlay` (dim+compose a modal panel over a base view), `card`, `confirmmodal` (`ConfirmCard` — the minimal y/n confirm card `browse`/`nodedetail`'s cordon/drain verbs still use; `TypeNameModal` — 8b's type-the-name PROD delete confirm, the app's other red-bordered surface), plus `palette` (the one jump/namespace/context modal shell) as its own subpackage.
- **`internal/tui/tasks/*`** — one package per screen: `browse` (the one resting screen for every resource kind — table, health strip, filter, empty state; Deployments get a ROLLOUT/IMAGE column pair and `R` rollout-restart as of Phase 7), `poddetail` (5a pod detail — status/termination banner/meta grid/containers/bars/events/sidebar, pushed from `browse`'s Pods list and `nodedetail`'s pod rows on `↵`), `nodedetail` (11b node detail — conditions/allocated-allocatable/taints facts panel over the node's own pods table, pushed from `browse`'s Nodes list on `↵`), `yamlview` (8a read-only syntax-highlighted YAML view, pushed by `y` on any object from `browse`/`poddetail`/`nodedetail`), `podlogs` (5b streaming log viewer — toolbar with container/since/wrap/timestamps, severity-colored lines, restart boundaries, on Chrome v2 as of Phase 6), `events` (9b deduped, severity-colored event feed — hand-rolled two-line rows, not `components.Table` — namespace-scoped from `browse`'s `e` or object-scoped from `poddetail`/`nodedetail`'s `e`, `↵` jumps to the involved object via a `tea.Sequence(BackMsg, GotoResourceMsg)`), `execpicker` (10a exec container picker — pushed by `x` on a Pod with more than one container from `browse`/`poddetail`; a single-container pod execs immediately without this screen), `secretdata` (27b Secret Data view — masked KEY/VALUE/SIZE grid, `a` line-inserts a new key, `↵` on an existing row decodes and re-edits its real value, `ctrl-d` removes one, pushed from `browse`'s Secrets list on `↵`), `configmapdata` (27a ConfigMap Data view — KEY/VALUE/SIZE grid, no masking since ConfigMap values aren't sensitive; `↵` edits a short value in place, `e` opens a multi-line buffer editor for a folded key, `ctrl-r` chains the apply with a rollout-restart of every consumer, pushed from `browse`'s ConfigMaps list on `↵`), `objectdetail` (14d generic CRD detail — meta grid from the kind's own printer columns, CONDITIONS, EVENTS, no per-CRD layout code ever, pushed from `browse`'s `↵` on any discovered CRD row), `overview` (19a cluster overview — capacity bars, nodes, cluster-wide trouble list, recent rollout changes; a routing layer, not the resting screen, reached only via `g "ov"`), `timeline` (16a/16b incident timeline — events, container restarts, and rollout revisions merged newest-first; namespace-scoped from `browse`'s `t`, object-scoped from `poddetail`/`nodedetail`'s `t`), `whocan` (22a RBAC who-can — resolves `(Cluster)RoleBindings`→`(Cluster)Roles` entirely from the informer cache, no server round-trip per query; the four RBAC informers it needs are lazy, so the first open of the screen fills them and reload lands via their change events; reached via `g "who"` or `w` from a 403 card), `routetable` (23a/23b Ingress/Gateway API routing table — one row per host+path or match, live backend resolution; pushed from `browse`'s `↵` on an Ingress or a discovered HTTPRoute/GRPCRoute/TCPRoute/Gateway kind), `forwardpicker` (13a port-forward picker — candidate ports discovered from the target object, `↵` starts the forward via `kube.ForwardManager` without suspending the program), `helmhistory` (18a Helm release revision rail — decoded straight from the release's own `helm.sh/release.v1` Secret, `R` rolls back through `kube.Mutator.HelmRollback`), `update` (28b what's-new panel — changelog plus the exact package-manager upgrade command, reached via the root shell's `U` key or the goto palette's `:update`; 28a's ambient header chip is driven by the same `*tui.Session.Update` state, populated by a once-per-24h release-feed check), and `setup` (the 4c/10b recovery screen the root shell shows when there's nothing else to render yet — an unreachable context or no kubeconfig found).

### The Task contract and navigation stack

`tui.Model` is the root Bubble Tea model. It wraps a single active `Task` and keeps a `stack []Task` for back-navigation:

- `Task` = `tea.Model` + `SetSize(w, h)`. Every screen implements it.
- When a task's `Update` returns a *different* task instance, the root pushes the current one onto the stack (this is how `browse` opens `podlogs` via the injected `OpenLogs` callback, on `l`).
- A `tui.BackMsg` pops the stack. Screens send `BackMsg` instead of quitting to return to the previous screen.
- The root also fans `tea.WindowSizeMsg` out to the active task's `SetSize`.

### Task package conventions

Each task package is split into files by responsibility: `model.go` (struct + `New`/`Init`/`SetSize`), `update.go` (message handling), `view.go` (rendering), `keys.go` (key bindings) — `browse` also has `sort.go`, `filter.go`, `selection.go`, `metrics.go`, and `hints.go` for its extra concerns. State is tracked with the shared `tui.TaskState` enum (`loading`, `ready`, `empty`, `error`, `permission-denied`, `confirming`, `success`, `cancelled`).

Mutating actions are designed to go through a `confirming` state before executing: screens embed an `actions.Controller`, press a mutating key → `Begin(tier, tui.TaskAction)` (the caller resolves `tier` via `verbs.TierFor(verb, isProd)` — `TierNone` verbs like cordon execute immediately; `TierInline`/`TierModal` move to `confirming`), then either `y`/`n` (`TierInline`, and every `TierModal` verb except delete/force-delete — e.g. Drain) or typing the resource's name + `enter` (`TierModal` delete/force-delete only, via `Confirm`/`TypeRune`/`Backspace`/`Escalate`) route to execution, and the `actions.ResultMsg` returned feeds `HandleResult`. Execution runs through `kube.Mutator`, so no screen calls a write verb directly. `browse`'s Nodes list and `tasks/nodedetail` call this for `C` cordon/uncordon (`TierNone`, no confirm) and `D` drain (`TierModal`, still `components.ConfirmCard`'s minimal inline card, unchanged since Phase 9 — deliberately not upgraded to the type-the-name modal). `browse` (any row, any kind) and `tasks/poddetail` call it for `ctrl-d` delete, which *is* tier-driven: inline `y/N` in non-prod, `components.TypeNameModal` (type-the-name + `ctrl-k` force-delete escalation) when the active context is tagged prod. `browse`'s own `m` labels/annotations editor (26a, `tasks/browse/meta.go`) is the first screen built to never let a commit close it: its `pendingMeta` gate stays set across the whole `Begin`/`Confirm`/`HandleResult` cycle (a join-locked edit's or a removal's `y/N` renders *inside* the still-open panel, not as a table-with-overlay), and `HandleResult` either re-fetches the object and refreshes the grid + shows an inline result line on success, or restores the exact pre-commit editing/add state with the server's error on failure — `esc` is the only thing that closes it. **"confirm → execute → refresh → show result → remain on screen" is the decided contract for every context-preserving inspector/editor, not just 26a** — docs/design README.md's §25a/§27a/§27b specify the same shape (SetResources' four-field apply, ConfigMap's per-key `↵`/`ctrl-r`, Secret's add-key flow). §27b is implemented (`tasks/secretdata`, pushed from `browse`'s Secrets list on `↵` — a full pushed screen with its own `› Data` breadcrumb segment, not a `browse`-embedded panel like 26a/25a, since the mockup's breadcrumb adds that segment past the object itself): `a` line-inserts a new key, `↵` on an existing row decodes its real value into the same visible-while-typing buffer for a rewrite (not a blind edit — an explicit departure from the original 27a-covers-editing split), `ctrl-d` removes an existing key. All three follow the same confirm/refresh/remain contract; `ctrl-x` (not a bare letter) toggles the mask on whichever buffer is open, so plain `x` stays typeable; the will-run band itself is omitted entirely — no rule, no placeholder line — whenever there's genuinely nothing to preview, appearing only once there's a real command/confirm/result to show; the will-run line and every result message always mask/omit the value, success or failure. §27a is also implemented (`tasks/configmapdata`, the same full-pushed-screen shape as 27b): `↵` on a short value edits it in place, `e` opens a 17a-style buffer editor scoped to just that value (apply key is `ctrl-o`, not 17a's `ctrl-s` — `ctrl-s` is the terminal XOFF key in some environments, so this one buffer editor moved off it), `ctrl-r` chains the apply with a rollout-restart of every workload named in the consumers strip; same confirm/refresh/remain contract as 26a/27b. §25a (`setresources.go`) is implemented but still closes the panel on apply (24a's older `SetImage`-style shape) and needs updating to match — don't copy `SetImage`/`SetResources`'s current close-on-commit code as precedent for new work, copy `meta.go`, `tasks/secretdata`, or `tasks/configmapdata`.

Namespace/context switching now dispatches for real: the root shell's `g`/`n`/`c` keys each open the one `components/palette` overlay (scoped Goto/Namespace/Context — `internal/tui/goto.go`/`namespace.go`/`context.go` build its `Item`s from `Session`), and `Enter` sends a navigation message (`GotoKindMsg`/`GotoResourceMsg`/`SwitchNamespaceMsg`/`SwitchContextMsg`) that the root `Update` uses to keep `Session.Location` authoritative before forwarding to the active task — `browse` handles all four. A context switch is the one that actually rebuilds the cluster: `kube.Cluster.SwitchContext` runs in a `tea.Cmd` (blocking, since it re-syncs the eager informer caches — the rest start again on demand, as at launch), so every `Session` read/write around it (recents, `PerContext` restore) happens synchronously *before* the `tea.Cmd` closure is built — the closure itself only touches the stable `*kube.Cluster` pointer. `?` opens a help overlay built from the active `Screen`'s own `Keybar()` (current-view column) plus `Session.HelpScope`/`HelpGlobal` (the fixed SCOPE/GLOBAL columns).

Dependencies are always passed via a package-local `Config` struct with interface-typed fields, and `New` fills in defaults for zero values. Follow this when adding a screen: define the interface you need in the task package, implement it on a `Client*` type in `kube`, and wire it in `app.NewModel`.

## Testing

Heavy use of table tests plus **golden-file** rendering tests under `test/golden/`, all following the same `UPDATE_GOLDEN=1`-guarded `TestGenerateGoldenFixtures` + comparison-test pattern:

- `internal/tui/components` (the `Table` component itself) against `test/golden/table/*.golden`.
- `internal/tui/tasks/browse` (full-screen 2a renders, 120×36 and 80×24) against `test/golden/browse/*.golden`, plus **forced-truecolor goldens in both themes** (`test/golden/browse/120x36-{dark,light}.golden`, ANSI included) — the fixtures that actually pin the Theme-token-to-cell color mapping, since the plain goldens render colorless under test. This is the pattern to copy for new theme-sensitive screens (`truecolorGoldenFixtures` in `browse/golden_test.go`): force the profile with `lipgloss.SetColorProfile(termenv.TrueColor)` + deferred restore. The profile is a global, so packages with truecolor goldens must not use `t.Parallel` in tests that render.
- `internal/tui/tasks/podlogs` against `test/golden/podlogs/`.

Anything about *what the app fetches* is tested against the fake clientset's recorded actions rather than through the UI (`internal/kube/lazy_test.go`, `helm_secrets_test.go`): assert which resources were listed, how many times, and with what field selector. That's the only way to catch a regression that renders identically but pulls the cluster down the wire — and when adding one, check it fails without the fix, since a test helper that builds its own informer factory can pass while proving nothing (hence `newTypedFactory`). `go test -race ./internal/kube` covers the lazy-start path, which is called from the Bubble Tea update loop while informers run on their own goroutines.

**End-to-end tests live behind the `e2e` build tag** (`test/e2e`, plus `internal/kube/e2e_lazy_test.go` which needs the unexported `kindInformers` map) and so never run under `go test ./...`. They need a cluster: `scripts/e2e-cluster.sh up` builds it (kind, because a real kubelet is what makes logs/exec/port-forward genuinely testable — kwok is only the scale substrate), then `go test -tags e2e -count=1 -timeout 15m ./test/e2e/... ./internal/kube/...`. See `docs/e2e-plan.md`. The harness drives the *real* `app.run` through a real `tea.Program` over pipes, and captures frames via `tea.WithFilter` rather than by parsing output — bubbletea's renderer emits cursor-relative diffs, which no amount of ANSI stripping turns back into a screen. Two rules keep it from going flaky and both are load-bearing: **no golden files** (a real cluster produces nondeterministic AGE, pod-name suffixes, IPs and node assignment — E2E asserts substrings and structural predicates, goldens stay the unit-level tool), and **no one-shot assertions** (caches fill asynchronously, so every check goes through `App.WaitFor`/`WaitLoaded`/`Never`, which poll against a deadline while pumping the event loop; a bare `strings.Contains` on the first frame is a race by construction, and a one-shot check for a *negative* passes simply by looking too early). A third rule earned the hard way: **never assert on transient state** — polling can't help when the value itself comes and goes. A crash-looping container reads `CrashLoopBackOff` only while it waits, and the list redraws only on a watch event, so a frame captured mid-restart holds a stale word for as long as the backoff (capped at five minutes); assert the durable statement of the same fact instead. Likewise wait for a *row* before pressing `↵`, not for the breadcrumb, which is on screen before the rows are. No E2E test may call `t.Parallel`: `Launch` isolates `HOME`/XDG with `t.Setenv`, and `internal/kube`'s own e2e tests set the kubeconfig path, both process-global.

When you change rendering output, regenerate with `UPDATE_GOLDEN=1 go test ./path/to/package` and review the diff rather than hand-editing fixtures. Tasks are tested by driving `Update` with synthetic messages and asserting on `View()`/`Render()` output or state — no live cluster needed because all `kube` access is behind interfaces (see `browse`'s `fakeLister`/`fakeMetrics` test helpers, or `kube/fake` for a whole-cluster fixture set).
