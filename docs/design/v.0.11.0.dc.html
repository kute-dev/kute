kubectl debug — one key asks for a shell, the object decides how

No new top-level key: x already means "get me a shell near this object". A running pod with a shell in the image → kubectl exec (10a). A distroless pod → ephemeral container. A pod that won't stay up → pod copy. A node → host-namespace pod. Which provider applies is a command-table declaration per kind, not a new screen.

  • Mode is two rows, not a form — the same selection grammar as every other list, and each row states when it applies. Pod state picks the default; `m` overrides.
  • Image, target and profile are edited in place on the row (13a's local-port idiom). Recents are remembered per context in the existing persisted state — no image registry, no config file, no wizard.

  • Replaces the legacy `s` node-shell. That key ran a privileged root shell with no will-run line and no PROD confirmation — the most dangerous action in the app had the least friction — and a node-only second key contradicts `x` being the one shell key. The key goes; its command stays.
  • The entrypoint is the default, not homework. `chroot /host` with bash-preferred, sh-fallback is what the legacy shell already did; the panel ships that shell instead of telling you to fix it after you land. One `shell` row states both facts.
  • Prefilled to exactly the legacy defaults, so `x ↵` is the old `s` — one extra key buys the will-run line and the PROD `y/N`. The panel is a receipt you can override, not a form to fill.
  • The node's pod count is the warning — a number from the data, not a scare string. In PROD contexts ↵ takes an inline `y/N`; the red modal still belongs only to delete and drain (8b).
  • Suspend/restore and the keybar failure line (`node shell exited: …`) carry over from `s` verbatim — same handoff as exec (10a).
  • Fits the nodes verb set next to `C` cordon and `D` drain, so the escalation ladder reads on one keybar.
